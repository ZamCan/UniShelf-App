# UniShelf Office V2

UniShelf V2 adds a genuine, fully offline LibreOffice-based document editor to
the existing UniShelf Android application. It does **not** replace the original
Flutter home screen, navigation, branding, colours, typography, layouts,
animations or data. The published UniShelf APK is used as the base, and an
additional `org.unishelf.office.OfficeActivity` is registered next to the
untouched `com.unishelf.app.MainActivity`.

## What is included

* The upstream MPL-2.0 LibreOfficeKit Java bridge (`org.libreoffice.kit`).
* `OfficeActivity`, a framework-only editor UI using the existing UniShelf
  palette and a document surface that draws tiles returned by LibreOfficeKit.
* The real arm64-v8a LibreOffice engine from the official F-Droid
  LibreOffice Viewer 26.2.7.3 package (`versionCode 135`), including native
  libraries, filters, fonts, NSS, configuration and runtime assets.
* Blank Writer, Calc and Impress templates generated by that engine, plus ODF
  templates.
* Open, Save, Save As, PDF export, printing, page navigation, undo/redo,
  character formatting, paragraph alignment, bullet/numbered lists,
  zoom/pan, soft-keyboard editing and password prompts.
* Atomic local saves (`.saving` then rename through `.bak`) and recovery of a
  newer interrupted-save copy when the same document is reopened.

There is no online service, cloud upload, hidden network call or simulated
document result in this feature. LibreOfficeKit runs on the device. All file
access uses Android's Storage Access Framework or a user-granted `file://` /
`content://` URI.

## How to use it

The original application is not modified in the APK. After installing the
augmented build, open a supported document with Android's system **Open with**
or **Share** chooser and choose **UniShelf Office**, or launch the activity
directly:

```text
unishelf://office?type=writer
unishelf://office?type=calc
unishelf://office?type=impress
```

The original **UniShelf** entry remains available and keeps its original
behaviour. A user can therefore keep using the existing study workspace while
the Office editor is an explicit, opt-in destination for documents.

## Supported formats

Opening and editing is provided by the corresponding LibreOffice import
filter. The normal save path retains the original format when possible:

* Text: DOCX, DOC, ODT, RTF, TXT, PDF (PDF is opened as a fixed-layout Draw
  document)
* Spreadsheets: XLSX, XLS, ODS, CSV
* Presentations: PPTX, PPT, ODP

PDF export and Android's print framework are available for every document
type. Exporting to a different format is deliberately warned about because
LibreOffice's conversion can change layout and unsupported markup. Macros are
never executed. Some complex PDF editing, embedded media, external links,
digital signatures, tracked changes and advanced OOXML/ODF features may not be
preserved by the upstream import/export filters.

An unmodified document is never rewritten. The editor works on a cache copy;
the original URI is only written when the user explicitly taps Save, and then
only after a temporary LibreOffice output has been atomically committed.
Saving a legacy binary (`.doc`, `.xls`, `.ppt`) or editing a PDF shows a
fidelity warning before the first write.

## Build

See `tools/build-office-apk.sh`. It downloads the public base release and the
official F-Droid LibreOffice APK, verifies their SHA-256 checksums, extracts the
arm64 engine, compiles the Java bridge, creates `classes2.dex`, registers the
activity without changing resource IDs, and produces a debug-signed APK.

The base APK is pinned to:

```text
UniShelf-arm64-v8a.apk
sha256 f67f918ad2e7f615f8a344dfd84f3aff7e05187ad763963258f3998084613902
```

The engine source is pinned to:

```text
LibreOffice Viewer for Android 26.2.7.3 (F-Droid versionCode 135)
sha256 e921bfb14170824572eb1e33643538803681226427948c245084f5e6356c3775
```

The delivered test APK is debug-signed. The original release signing key is
not available, so it **cannot update or overwrite an installed original
UniShelf 1.0.0 release**. To test it, uninstall the original first (after
backing up any app data you need) and install the debug build. No production
release or app-store submission is made from this work.

## Verification

The native engine was exercised directly with genuine documents using the
upstream `LibreOfficeKit` C API, and the repository includes an on-device
self-test path that loads a real DOCX, paints a tile through the engine, sends
an editing command through LOK's Java bridge, exports DOCX and PDF, and records
the actual output byte sizes. The CI workflow runs that self-test on an arm64
Android emulator. It is guarded by `android:debuggable` and is not part of the
production build path (`SELFTEST=0`).

See `docs/VERIFICATION.md` for the recorded native results and the workflow
diagnostics.

## Limitations and honest status

* The original Flutter source and release signing key are not in this
  repository, so an in-place source merge and an in-place upgrade of the
  released app are impossible.
* This is an APK augmentation, not a rebuilt Flutter application. The original
  `classes.dex` and Flutter assets are preserved byte-for-byte.
* The complete LibreOffice Viewer UI was not merged. The added editor is a
  deliberately small platform UI; it exposes the real engine but does not
  reimplement every LibreOffice command or dialog.
* The engine is arm64-v8a only, matching the original arm64 release artifact.
  The armeabi-v7a release is not augmented.
* The debug APK cannot be installed as an update over the release-signed app.
* Runtime testing requires an arm64 Android device/emulator; this environment
  has no locally executable arm64 Android emulator. The native engine tests and
  the GitHub Actions emulator job are the available execution evidence.
